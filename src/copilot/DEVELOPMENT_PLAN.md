## 1. MVP 边界（P0 做什么 / 不做什么）

**做**：单票查询 → 费率匹配 → 应有 vs 已录比对 → 差异清单 → 四级追溯链 → 一个原生 HTML 页面 + 一条 curl 脚本能走完。

**不做（留给 P1/P2）**：Harness 知识库接入、知识图谱、六类差异全量归因、审计日志落库、导出留痕、复核审批流、多客户权限细分。

> 判断依据：MVP 要证明"这套逻辑真能拦住漏收"，而不是"页面好看"。所以 P0 优先把 BK2610-0187 这一票跑出 3 条缺项 ¥2,610。

## 2. P0 任务（MVP，7 项）

| ID | 任务 | 依赖 | 产出 | 验收标准 |

| P0-1 | 工程骨架补齐 | — | `app/db/{models,session}.py`、`app/services/` 目录、`requirements.txt` 定稿 | `python -c "import app.main"` 通过；`/health` 返回 ok=true |

| P0-3 | 种子数据 | P0-2 | `scripts/seed_demo.py`：BK2610-0187 一票 + 客户 C-0731 + 两份费率卡（V3/V4）+ 船司账单 4 行 | 脚本可重复执行（幂等）；`sqlite3` 查得 1 票 / 6 费用行 / 2 费率卡 |
| P0-4 | 归集服务 | P0-3 | `services/collect.py`：四键查询、按箱分行、未归集池 | 用 `BK2610-0187` 与 `HLCUNB26100457` 查同一票返回一致；未归集行为空 |
| P0-5 | 费率匹配 + 应有费用 | P0-4 | `services/rate.py`：按 `bl_date` 选费率卡版本、输出应有费用行（含依据） | 2026-10-09 的票命中 **V4**（不是 V3）；缺费率卡时返回 `BLOCKED` 而非默认值 |
| P0-6 | 差异比对 + 追溯链 | P0-5 | `services/diff.py`（缺项/重复/金额不符三类）、`services/trace.py`（四级 + 断链标注） | 对 BK2610-0187 输出 **3 条缺项合计 ¥2,610**（1180+980+450）；追溯链第 4 级标"待出账" |
| P0-7 | 最小前端 + 自测脚本 | P0-6 | `web/index.html`（原生 JS 单页）、`scripts/selftest.py`、`verify.sh` 更新 | 浏览器输入四键能看到三块结果；`bash verify.sh` 全绿；`python scripts/selftest.py` 无第三方依赖即可跑出 ¥2,610 |

| GET | `/shipments/{key}` | 单票头 + 费用行 |

| GET | `/trace/{charge_line_id}` | 四级追溯链 |
| GET | `/` | 演示页面 |

## 3. P1 / P2 任务（P0 验收后再排期）

| ID | 任务 | 依赖 | 优先级理由 |
|---|---|---|---|
| P1-1 | 权限矩阵落地（角色 × 能力 × 客户 scope） | P0-4 | 红线 1、4；没有它不能叫"内部系统" |
| P1-2 | 审计日志（查询/导出/越权，只追加） | P1-1 | 红线 3；导出留痕的前提 |
| P1-3 | 复核闸门（草稿 → 提交 → 审批，禁止自动发送） | P1-2 | 红线 5；业务上最关键的人工控制点 |
| P1-4 | 导出追溯包（字段白名单 + 留痕） | P1-2 | 客户答疑场景闭环 |
| P1-5 | 六类差异全量归因（补齐归属错误/汇率/账单拆行） | P0-6 | 812 条差异里 18% 是拆行假差异，不处理会误判 |
| P2-1 | Harness 知识库接入（带出处检索） | P0-1 | 红线 7；条款解释必须可溯源 |
| P2-2 | 知识图谱（kg_triple + 2 跳扩展 + GraphRAG-lite） | P2-1 | 回答"为什么这条规则适用这票" |
| P2-3 | 指标看板（漏收率/周期/一次通过率） | P1-2 | 验收指标要对得上基线 |
| P2-4 | 评估集与回归（200 票 / 34 票已知漏收） | P0-6 | 证明识别率 ≥95%、误报 ≤5% |

## 6. 交付节奏（每阶段四件套）

P0 完成时我给你：

1. **变更文件清单**（新增/修改逐个列）
2. **启动与自测命令**（含 `pip install` 与本机替代方案）
3. **可直接跑通的验证脚本**（`scripts/selftest.py` + `verify.sh` 两个）
4. **本阶段最可能出问题的三处**（按实际写，不套模板）

然后**停下等你确认**，再进 P1。

---

## 7. 需要你确认的 3 件事

1. **MVP 范围认可否**：P0 不接 Harness、不做知识图谱、不做权限细分——只做"单票差异 + 追溯链"，够不够作为原型？
2. **运行环境**：你本机 `pip install fastapi uvicorn pydantic pyyaml sqlalchemy` 能装吗？（决定 MVP 是"我这边演示"还是"你那边验证"）
3. **演示数据**：沿用 BK2610-0187 这一票（3 条缺项 ¥2,610），还是你想换一票/加两票做对照？

回复"确认 + 这三点的答案"，我立刻开 P0-1。
