你是资深 AI 应用工程师，帮我开发一套面向贸易服务结算场景的「结算复核助手」智能体系统。请严格按我给出的技术栈和约束执行，不要自行替换框架、不要引入我没要求的中间件。

【项目背景】
委托方是宁波海川国际贸易服务有限公司（贸易服务部 / 结算组），做出口一站式贸易服务：订舱、报关、拖车、仓储。2026 Q3 结算 1,268 票、应收 ¥4,386 万，但漏收 ¥78.9 万（占 1.80%），客户账单一次通过率只有 71.3%，结算周期中位 11.5 天，单笔差异追溯要 42 分钟，季末"待查"挂账 ¥120 万。一线就 3 个结算专员 + 4 个单证操作员，靠 Excel、共享盘和企业微信干活：船司附加费写在邮件正文里、客户费率卡在共享盘上有 7 个"最终版"、账单靠 Excel 手工拼 41 行。触发事件是 BK2610-0187 一票漏收 ¥2,610（LSS 1,180 + PSS 980 + 改配费 450），客户援引合同"7 日无异议"条款拒补，单票毛利从 8.2% 变成 -1.4%。

【系统定位】
做一个「结算复核助手」：内部工作台，不是给客户用的聊天机器人。结算专员输入一票业务（订单号 / 订舱号 / 提单号 / 箱号），系统检索公司制度与费率规则，输出三样东西——① 逐行费用结构（应收 / 应付）；② 应有费用 vs 已录费用的差异清单（缺项、重复、金额不符）；③ 任意一笔费用的追溯链（来源单据 → 费率条款 → 承担方 → 凭证），并标出断在哪一级。必要时调用工具生成追溯包草稿与待办。所有面向客户的内容，必须经结算专员人工确认后才可发出。

明确不做：自动开票、自动对外发送账单或补收函、自动修改费率卡、自动判断合同异议期是否已过。

【用户与权限】
- 结算专员：查自己负责客户的单据、生成追溯包草稿、提交复核；不能导出全量、不能改费率。
- 单证操作员：只能录入 / 查看自己经手票的费用行；看不到毛利率。
- 财务 / 复核人：可看全量、审批补收与减免、导出（强制留痕）。
- 合规 / 审计：只读全站操作日志与导出记录，不能改任何业务数据。
- 管理员：仅在后台配置费率卡版本、金额阈值、提示词；不做业务对话。
- 外部客户：不直接使用本系统，任何对外输出都经由结算专员转达。

【业务口径，必须遵守】
- 结算周期 = 提单签发日 → 客户账单发出日，不含客户账期，不许改口径。
- 漏收率 = 漏收金额 ÷ 同期应收总额。
- "应有费用"来自客户费率卡（版本 + 生效区间）+ 实际作业项，不来自历史账单。
- 异议期按客户合同读取（标准 7 日、部分年度协议 15 日、未约定走催告 30 日），禁止硬编码 7 天。
- 金额一律用 Decimal，禁止 float 参与金额运算；币种必须显式标注。
