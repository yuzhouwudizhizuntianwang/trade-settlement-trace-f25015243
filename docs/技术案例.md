# 技术案例：BK2610-0187 漏收追溯（端到端走查）

| 项 | 内容 |
|---|---|
| 案例编号 | CASE-001 |
| 业务单据 | 订单 SO2610-0187 / 订舱 BK2610-0187 / 提单 HLCUNB26100457 / 箱 MSKU1234567 |
| 客户 | 宁波恒晟机电（C-0731），年度费率协议 2026-01 版 |
| 航线 / 箱型 | 宁波 → 鹿特丹 / 1×40HQ |
| 结果 | 漏收 ¥2,610（LSS 1,180 + PSS 980 + 改配 450），单票毛利 8.2% → -1.4% |
| 系统角色 | 结算专员 陈莉莉（settler，scope=["C-0731"]） |

---

## 1. 输入（一句话，四个键）

> "帮我复核 BK2610-0187，明天要出账。"

系统只接受四键（订单号 / 订舱号 / 提单号 / 箱号）；**不接受**"恒晟那个大客户的单子"这种描述——因为客户范围必须落成 ID 才能做权限校验。

---

## 2. 第 1 步：归集（`collect`）

| 来源 | 拿到什么 | 系统处理 |
|---|---|---|
| CargoWare 只读 API | 单票头：客户 C-0731、bl_date 2026-10-09、航线 NINGBO→RTM、箱型 40HQ | 建立 `shipment` 上下文 |
| 费用行 | 5 行应收（OCF 1850 USD、THC 1260、CUS 380、TRK 1150、AGY 720）+ 1 行 SUR 金额 0、备注"LSS1180/PSS980（口头待确认）" | 识别 SUR 行金额为 0 → 进"疑似缺项"候选 |
| 供应商账单 | 船司 2 张（10-09 主单、10-23 补发） | 解析成 4 行应付（含 REB 450） |
| 未归集 | 无 | — |

**关键动作**：`fee_remark`（自由文本）命中规则词典 → 抽出 `LSS`、`PSS` 两个费用代码，但**金额不从备注里取**（备注可能过期），金额必须回到费率卡。

---

## 3. 第 2 步：应有费用（规则引擎 + 知识图谱）

### 3.1 图谱 2 跳：这票适用哪一版费率？

```
(Customer:C-0731) --HAS_CONTRACT--> (Contract:HC-2026-011)
(Contract:HC-2026-011) --HAS_RATE--> (RateCard:V3, 2026-06-01~2026-09-30)
(Contract:HC-2026-011) --HAS_RATE--> (RateCard:V4, 2026-10-01~  ...)
(RateCard:V4) --COVERS--> (FeeItem:SUR-LSS, unit 1180 CNY/40HQ)
(RateCard:V4) --COVERS--> (FeeItem:SUR-PSS, unit 980  CNY/40HQ)
(FeeItem:SUR-LSS) --GOVERNED_BY--> (PolicyClause:HC-FIN-2024-07 §5.2)
```

**推理结果**：bl_date = 2026-10-09 → 落在 **V4**（10-01 起生效）；而出账实际引用的是 V3。图谱这一跳直接把"版本错配"变成可解释的事实，而不是一句"用错了"。

> 如果只做向量检索，会召回"5.1 费率卡须登记版本"这段文字，但**不知道**这票该用 V4——这正是引入知识图谱的理由。

### 3.2 生成应有费用

| 费用项 | 应有金额 | 依据 |
|---|---|---|
| OCF 海运费 | 1,850 USD | RateCard V4 · 航线 NINGBO-RTM · 40HQ |
| THC | 1,260 CNY | V4 |
| CUS | 380 CNY | V4 |
| TRK | 1,150 CNY | V4 |
| AGY | 720 CNY | V4 |
| **LSS** | **1,180 CNY** | V4（2026-10-01 调价）+ 条款 §5.2 |
| **PSS** | **980 CNY** | V4 旺季区间 10-01~12-31 |
| **REB 改配费** | **450 CNY** | 船司 10-23 补发账单 + 委托单变更记录 |

---

## 4. 第 3 步：差异清单（`diff`）

| # | 类型 | 费用项 | 金额 | 证据 | 归因 |
|---|---|---|---|---|---|
| 1 | 缺项 | LSS | 1,180 | 船司账单 MSK-INV-26-10-0912 第 2 行 | 费率卡版本未同步（V3 vs V4） |
| 2 | 缺项 | PSS | 980 | 同上第 3 行 | 同上 |
| 3 | 缺项 | REB 改配费 | 450 | 船司 10-23 补发账单；企业微信群 10-20 通知 | 群内信息未进系统（X-01） |
| 4 | 金额不符 | OTH 其他费用 | 260 | 客户账单第 6 行 | 费用名称不规范，应拆为仓储费（客户侧异议） |

**合计缺项 ¥2,610**，与财务月结发现金额一致。

> 系统同时拦下一条假差异：船司主单把 THC 拆成"码头操作费 + 安保费"两行，先合并再比对，避免多算一条差异（对应技术方案 §8.2 第 6 类）。

---

## 5. 第 4 步：追溯链（`trace`，以 LSS 为例）

| 级别 | 内容 | 状态 |
|---|---|---|
| ① 来源单据 | 船司账单 MSK-INV-26-10-0912（2026-10-09 到司）；原件 `data/src/MSK-26-10-0912.pdf#p1` | ✅ |
| ② 费率条款 | 合同 HC-2026-011；RateCard V4（2026-10-01 起）；《结算与费用管理办法》§5.2、§3.2 | ✅ |
| ③ 承担方 | 客户 C-0731（合同 §3.1 约定附加费实报实销） | ✅ |
| ④ 凭证 | 待出账（账单行号未生成） | ⚠️ 未完成 |

**输出**：`断链：无；第 4 级待出账后回填`。系统不会因为"差最后一级"就标成完整——AC-05 的零容忍项就是"虚假完整"。

---

## 6. 第 5 步：人工确认闸门

系统产出的是**草稿**：

```
草稿：为 BK2610-0187 补录 3 项应收（LSS 1,180 / PSS 980 / REB 450），
合计 ¥2,610，客户账单金额将由 ¥3,510 调整为 ¥6,120。
风险提示：该票提单日 2026-10-09，客户合同异议期为 7 日，
         当前 2026-11-03 已超期，补收需走商务协商，不得自动发送。
```

| 谁 | 能做什么 | 不能做什么 |
|---|---|---|
| 陈莉莉 settler | 提交复核、附说明 | 不能直接改账单金额、不能发送 |
| 周慧 reviewer | 批准补收 / 驳回 / 减免 | 不能改费率卡 |
| 系统 | 生成草稿、留痕、提醒超期 | **绝不能自动发出**（红线 5） |

本次实际结局：客户援引 §7.2 拒补，公司认损 ¥2,610。**系统没能救回这一单，但把"为什么救不回"变成了三条可举证的差异记录**——这正是阶段 02 报告里"事后追认已无合同抓手"的现场证据。

| 环节 | 人工现状 | 系统介入后 | 差异 |

| 发现漏收 | 月结（11-03），距提单 25 天 | 出账前（10-25 当天） | 提前 9 天，仍在异议窗口内 |

> 口径提醒：表中"提前 9 天"是按 10-25 出账测算，属于**假设推演**，不是实测。真实收益要等试点 30 票回放后才有数字。

---

## 8. 这个案例暴露的三个设计约束

1. **金额不能从备注里取**。`fee_remark` 里写着"LSS1180"，但 10-01 已调价；备注是线索，不是依据。
2. **异议期不能硬编码**。本合同 7 日，另有客户 15 日；系统只能读合同字段，不能写死。
3. **假差异必须先合并**。船司拆行若不处理，会多出一条差异、把归因指错人。
