## 一、决策链（只能问出来，查不出来）

| 角色 | 姓名 / 职务 | 在本项目中的决定权 | 不能决定什么 | 依据原话 |
|---|---|---|---|---|
| **发起人（Buyer）** | 王振华 / 总经理 | 立项、范围终裁、继续或停止、跨部门协调 | 不审单笔金额；不介入技术选型 | "Q4 把漏收压到 1% 以下，这件事我盯。" |
| **出资者 / 预算审批** | 周慧 / 财务总监 | 48 万预算，≤50 万自行审批；>50 万需总经理办公会 | 不能改业务范围 | "50 万以内我签，超了要上会。" |
| **业务使用者（主用户）** | 陈莉莉 / 结算专员 | 需求细节、字段口径、日常使用 | 无权定阈值（阈值要业务认） | "我只想开票前告诉我少了什么。" |
| **业务使用者（次用户）** | 张伟 / 单证操作员 | 录入侧字段与流程 | 同上 | "别让我多录一遍就行。" |
| **下游使用者** | 李文静 / 客服主管 | 客户答疑视图需求 | 无 | "客户要的是能看的单据，不是解释。" |
| **技术负责人** | 刘建国 / 信息化负责人 | 系统边界、接口方案、上线窗口 | 不能改业务口径 | "CargoWare 只读，别指望我让它写回去。" |
| **风险 / 合规（红线）** | 许安 / 法务与合规主管 | **一票否决**：数据出网、客户价格披露、合同条款解释 | 不参与技术选型 | "价格不能出公司网络，导出必须留痕。" |
| **Brief 持有人** | 赵磊 / 贸易服务部经理 | 书面范围、交付时间、排除项的解释 | 无预算权 | "任务书 V2.1 是唯一有效的版本。" |

### 关键发现：决策链有三个"卡点"

1. **预算卡点**：周慧的 50 万线决定了方案天花板，任何超过 48 万的设计都要重做（阶段 04 报价必须卡在这个数内）。
2. **红线条**：许安的一票否决权在"客户价格出网"和"导出留痕"两件事上，这直接否决了两种常见方案——云端 SaaS 比对、无痕批量导出。
3. **口径卡点**：赵磊的"5 天"和陈莉莉的"拿不到账单"直接冲突（M-02），这个冲突不解决，验收必然打不完。
